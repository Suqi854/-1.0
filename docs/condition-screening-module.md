# Client-only condition module

Site service1.27.0 includes modules/condition-screen0.1.3 and a separate static editor at /condition-screen/ui/index.html. The existing screening area links to it in a new window, preserving the main workbench's selection and inputs. The running privateSite1.27.0 retains its original14 MCP tools and schemas. This reduced public source1.27.0-public.2 retains14 legacy names, with four explicit unsupported tools (get_stock_directory, get_auction_snapshot, get_auction_series and get_archive) and a fixed-explicit cloud swing schema; see public-distribution-profile.md. Neither profile provides a cloud custom-rule tool.

The editor is an explicitly synthetic demonstration. Its10 invented pool rows and invented OHLCV windows are not a real industry-leader universe, a completed data update or screening of actual stocks. Real curated identities and private preferences are handled by later local integration using docs/local-ohlcv-dataset-contract.md. The data updater and condition consumer do not select leaders.

Rules support bounded declarative AND/OR groups, D/W/M fields and indicators, comparisons, windows, offsets and crosses. The consumer exposes pass/fail/unknown with per-condition values, dates and quality evidence; failed, insufficient and unprocessed members remain in coverage. Amount, finance, fund-flow, market-cap and turnover conditions are unavailable without their required data. qfq week/month are not inferred from the prepared four-key dataset. Each batch is bounded and belongs to one frozen generation; changing a rule recomputes existing local observations.

Editing and evaluation occur in browser memory. A clicked download uses a local Blob URL; the rule is not put in a navigation URL, transmitted to an API, stored on the server, added to telemetry or written to browser storage. The condition page's response CSP sets connect-src and worker-src to none, form-action/base-uri/object-src to none, and allows only the reviewed same-origin static script/style assets. Static requests use an exact13-file allowlist, have no environment/database/source access, and reject mutation methods. Package metadata, documents, tests and fixtures are not served by this route.

The asset registry is deterministically generated by scripts/build-condition-assets.mjs from the explicit UI/src whitelist, without runtime data, credentials or environment reads. modules/condition-screen retains source/tests and generic documentation. The original package's HANDOFF, DELIVERY, SHA256SUMS and environment/test evidence are excluded from this integration and public export; a stale original DELIVERY record is not used as current release evidence.

Independent review reran190 pure module tests and closed the input-quality, frozen tuple, cutoff, bounded-ledger and report-alias cases. The author's32 browser checks describe its standalone synthetic UI only; they were not independently rerun in this environment. Integrated offline DOM checks cover local editing/evaluation/download and zero data/telemetry/storage calls, but are not real-browser layout or visual acceptance. No real leader-pool validation, local source activation, performance backtest or trading result is established by this module.
