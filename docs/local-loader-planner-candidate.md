# Local loader/planner development candidate

This is development copy 1.28.0-dev.3, built from the frozen and reviewed 1.28.0-dev.2 source. Public Git remains the separate 1.27.0-public.2 release; the owner-private Site remains 1.27.0. No timer, daemon, operating-system schedule, browser refresh loop, real market call or local installation is activated by this candidate. All evidence described here uses invented inputs and mocked HTTP.

`portable/local-public-loader.mjs` is an explicit, no-credential Node adapter. It requires an open immutable SQLite capability and uses four fixed Tencent fqkline sequences: raw D200/W104/M60 and qfq D200. It reuses the existing parsers, omits credentials, rejects redirects, caps response bodies at 1MiB and propagates cancellation with a maximum6.5s request timeout. It has no hidden retries or fallback to another OHLCV provider. Source rights/finality remain unknown and observations are local-only; public accessibility is not a retention or commercial-redistribution licence.

Every actual HTTP attempt, including both normal quote providers, is counted. Per-source starts are separated by at least1s, with global concurrency≤3; name/series work uses at most2 slots, preserving a slot for fast quotes. 429 yields a bounded cooldown; 401/403 pauses that source until explicit local resume. Cooldown/pause survives another adapter instance for the same live local capability. An optional attempt ceiling is per instance and is never reset by a timer. A new instance does not clear source pause or cooldown. Deadline/cancellation that an injected source ignores keeps its slot occupied until the late operation actually settles.

During an explicit tail invocation, Tencent is reserved for OHLCV and one-time research-name batches. Eligible Sina fast quotes can continue, with complete source snapshots and explicit zero-attempt reserved/paused outcomes. `loadNameQuotes` uses one fixed Tencent batch of at most20 symbols. Source/attempt/rate budget metadata is distinct from loader callback counts. A1s requested fast-quote goal is not a promise that a provider updates every second or that all research members are sampled every second.

`portable/local-update-planner.mjs` is synchronous planning only. `fast_quote_symbols` contains at most20 explicitly supplied local subscriptions. The independent `research_pool_symbols` or `research_pool_size` is the postclose denominator, not an implicit quote subscription. The verified2026 Asia/Shanghai calendar gates09–16 quote plans and the same-day15:35–16:00 tail plan. Unknown calendar coverage and nontrading days have no eligible work. Stable due keys suppress duplicates/clock regressions, and no old-day backlog storm is generated. Persisted acknowledgements and any later scheduling integration belong to the trusted host; this module registers nothing.

The OHLCV manifest optionally adds `observation_revision` and `identity_observation_hash`. The revision is a bounded identifier in the run hash, not a private strategy. Identical revision and frozen inputs are resumable; an intentional same-session revision creates a new immutable run. A retry fills only missing series and never refetches or changes an already-ready series. Existing legacy inputs retain their old run-hash behavior. A changed pool, target, calendar, evidence or name-observation hash also creates a distinct generation.

`portable/local-name-observation.mjs` validates each selected quote's provider, source timestamp, request/receipt clocks, body hash and decoded-name binding. It produces a separate local identity-observation hash tied to the approved research hash. It preserves the original members and research header. Fresh names get dated observations; a new ST name is explicit, while rename/missing/stale/invalid receipts remain counted and do not get a fabricated current observation. No name hint becomes official non-ST, active suspension or tradability certification. The bridge retains all frozen members; it cannot quietly shrink the denominator. Integrity hashes are not exchange authenticity proofs.

`portable/local-data-update-host.mjs` accepts only matching live Node capabilities: the original immutable SQLite instance, a real OHLCV store factory instance and a loader bound to that same instance. It rejects D1/counterfeit/closed contexts before argument access. One shared update invocation runs at a time; its identity reservation is owned before any caller clock work and remains owned through cleanup. Pause aborts the in-flight request and invalidates the writer fence. Store operations and each source callback recheck all live local capabilities; host clock callbacks also receive checks before and after they run. Admission and cleanup failures clear overlap/source reservations. A failing clock cannot prevent deadline rejection or cancellation; regressing receipt clocks are rejected, and a loader clock callback that closes its source adapter's SQLite capability cannot dispatch a request. The loader is env-bound; the OHLCV-store checks belong to the host callback boundary. It opens no database, registers no task and receives no condition rule.

Each advance retains≤20 stocks,≤80 loader invocations, concurrency≤3 and a24s start budget. Throttle/deferred calls can produce partial or pending-source state without making an HTTP request; adapter metadata separately reports actual attempts. Per stock all four observations must be committed before ready. `eligible = ready + partial + pending_source + failed_without_data + pending`; all_processed differs from all_ready. W/M may be forming, historic calendar proof remains limited and source final revisions remain unknown.

Condition recomputation uses the same frozen run/target/calendar/policy/manifest tuple via≤20-stock reads. Changing a rule does not call the source loader. The synthetic21-stock integration covers name receipts, identity hashes, bounded multi-advance publication, coverage reconciliation and two opposite rule thresholds with zero additional source calls. Separate cases exercise simultaneous fast quote/tail, shared-host overlap, pause/abort and rejected capabilities. These establish code invariants, not real-source accessibility, a running15:35 job, actual101-member coverage or a trading result.
