# Research-only next-stage contract

Development copy1.28.0-dev.2 / condition0.1.4 is separate from the separate public-distribution release and the running privateSite1.27.0. It has not been deployed, pushed to Git, bound to real market sources or activated on the user's local project.

`importResearchUniverse(input,{expected_file_sha256?})` is a pure asynchronous importer. It validates exact public-research-universe-v1 fields, supported mainboard identities, NFKC issuer names, typed dated no-ST-name observations, independent official unknown states, sector bound and canonical research/pool hashes. Public URLs are provenance only and never fetched; credential/private-query URLs and duplicate JSON keys are rejected. Null/month/day disclosure-date precision remains unchanged. The optional file checksum applies to original JSON text bytes, not reserialized objects. No actual101-member research artifact is included in the source or synthetic fixtures.

The importer separates `identity_header`, legacy-compatible `updater_input` and `condition_directory`. Its name observation stores an `asOf` date for condition freshness and `observedAt` for the original+08:00 timestamp. The research-universe hash is not a public-directory hash. `prepare({...updater_input,research_identity:identity_header})` freezes the local selected identities and header without requesting or pretending to verify the full official directory. Status explicitly reports research identity integrity/name observation, directory_identity_hash:null and no directory attestation. Sector, theme and business-evidence labels remain research metadata, not private strategy or source-request parameters.

`screen` and `createScreenLedger` accept an optional local `limits.evaluation_mode`. Its default or explicit strict value preserves the previous version1 behavior, ST-status and suspension checks and strict190-test contract. Explicit research_only retains all source/data/generation/clock/basis/calendar/coverage/lookback checks; it separates unknown official ST/suspension/tradability from a numerical price-volume study. A fresh dated no-ST-name observation and independent research identity header are required. Known ST or out-of-scope codes stay excluded; known suspension makes trading eligibility blocked. No unknown state is rewritten to non_st or active.

Research output has exactly the machine identifiers `version:2`, `result_contract:'ashare-research-screen-v1'`, `evaluation_mode:'research_only'`. Numerical judgments are in `research_rows` and `research_counts`; each row has `research_decision`, `research_passed`, original condition values/sample explanations and `trading_eligibility:{state:'unknown'|'blocked',actionable:false,...}`. Legacy `rows` are safe placeholders: passed:null, decision:unknown, state insufficient/failure/unprocessed, and legacy counts.match/no_match=0. Thus a consumer reading only the old passed/match fields does not receive a strict success. Research counts retain the separate finite-pool coverage equation.

An explicitly selected research mode also retains these version/mode/contract identifiers on invalid or blocked reports. Safely parsed, schema-valid research limits preserve this tag when snapshot/rule JSON fails its input boundary; malformed or unknown limits do not infer a mode. An unavailable input pool returns status blocked with both count ledgers null, preserving unknown coverage rather than inventing an empty successful pool. Valid strict blocked behavior remains unchanged.

`recognizeResultContract` is the renderer's machine gate. Browser input is JSON text. It types rows, errors, requested frames, requested-outside-pool lists, directory coverage and condition trees before rendering, and malformed reports return a bounded error. It rejects inconsistent mode/version/contract, legacy-success injection, duplicate symbols, research/legacy state or coverage disagreement, known-ST research candidates, conflicting suspension states, and actionable research claims. Failure and unprocessed states must agree by symbol between the two ledgers; a researched match/no-match/insufficient state has a legacy insufficient placeholder. The renderer clears prior results on a rejected contract or controlled render failure. The UI labels research matches and displays nonactionable trading eligibility. Its research toggle operates only on the existing synthetic demo, with no real pool embedding or network/storage calls.

The ledger freezes evaluation mode with local configuration. In research mode the frozen manifestHash must equal the independent researchIdentity.research_universe_hash; it cannot use a directory hash or arbitrary token. It carries neither mode nor private rule to data-read requests, uses existing≤20-stock/four-key reads, and maintains both safe legacy and research count ledgers without summing catalog counts. It preserves input/output isolation and the existing bounded budget. A changed rule or mode recalculates the same frozen observations; it does not start a loader or scheduling task.
